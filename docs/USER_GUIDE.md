## 1. Getting Started

### 1.1 Creating Your Account

1. Go to the platform homepage and click **Register**
2. Enter your email and a strong password
3. Verify your email via the confirmation link
4. Log in

### 1.2 Plans & Pricing

| Plan | Price | What You Get |
|---|---|---|
| **Free Trial** | 24-hour demo | All core modules, limited accounts |
| **Starter** | $29/mo ($290/yr) | 5 accounts, 3 campaigns, core modules |
| **Pro** | $79/mo ($790/yr) | 20 accounts, unlimited campaigns, all modules |
| **Agency** | $199/mo ($1,990/yr) | 50+ accounts, team seats, priority support |

PRO modules (Forwarder, Interceptor, Cloner, Reporter, GPT/Neuro) require Pro or above.

### 1.3 Connecting Telegram API

Before anything works, you need API credentials:

1. Go to **my.telegram.org** → API Development Tools
2. Copy your `api_id` and `api_hash`
3. In the app, go to **Settings → Telegram API**
4. Paste both values, set a session path
5. Click **Save & Reload**
6. Wait for green **Connected** status

### 1.4 Proxies

Proxies are strongly recommended for all operations.

**Supported types:** HTTP, SOCKS5, Mobile (Rotating / Sticky)

**To add proxies:**
1. Go to **Settings → Proxies**
2. Paste proxies (one per line: `host:port:user:pass`)
3. Click **Check Pool** to validate
4. Enable **Auto-assign proxies to accounts**

> For restriction removal, use **sticky proxies** (fixed IP). Rotating proxies perform poorly for captcha-related tasks.

## 3. Account Management

### 3.1 Account Registration

Register new Telegram accounts via SMS services — no phone required.

1. Go to **Accounts → Register**
2. Select an SMS service (sms-activate standard supported)
3. Enter the phone number without `+`
4. Select gender: Male, Female, or Random
5. Choose name type (English, Russian, or custom)
6. Attach a Parameter Database (generated by Parameter Generator)
7. Choose email type — **Gmail (Premium)** recommended for higher trust
8. Click **Start Registration**

**Options:**
- **Multi-service fallback:** If one SMS provider fails, the system tries the next
- **Random device parameters:** Each account gets unique fingerprint values
- **2FA auto-configuration:** Enable to set 2FA on registration

### 3.2 Parameter Generator

Generates realistic device fingerprints so each account looks like a unique device.

1. Go to **Accounts → Parameter Generator**
2. Set the number of parameter sets
3. Choose device types (Android, iOS, Desktop)
4. Click **Generate** and download the `.json` file
5. Use this file during registration

> Same fingerprint across multiple accounts = higher ban risk. Always generate fresh params.

### 3.3 Account Panel

Central hub for viewing, organizing, and editing accounts.

1. Go to **Accounts → Panel**
2. Accounts are organized in folders: Active, Flood Wait, Spam Block, Frozen, Archive
3. Select one or multiple accounts for bulk actions

**Bulk actions:**
- Edit Name / Bio / Avatar — update profiles across accounts
- Check Status — real-time restriction check
- Move to Folder — organize by status
- Delete — remove accounts
- Export — backup session data

### 3.4 Health Checker

Performs a real Telegram connection check — no simulation.

1. Go to **Accounts → Health Check**
2. Select accounts to check
3. Click **Run Health Check**

**Possible results:**

| Result | Meaning |
|---|---|
| Active | Account is clean |
| Flood Wait | Rate-limited, will auto-resume |
| Spamblock (Temp) | Temporary restriction |
| Spamblock (Perm) | Permanent restriction |
| Session Expired | Needs re-auth |
| Unauthorized | Invalid session |

### 3.5 Flood Auto-Resume

The system monitors all flood-wait accounts continuously. When a wait expires, the account is automatically moved back to Active.

**Manual trigger:** Go to **Accounts → Flood Resume** → click **Check & Resume All**

The **Flood Wait Dashboard** shows each affected account and its remaining wait time.

### 3.6 Account Booster (Warm-Up)

Warms up fresh accounts by creating realistic conversations between them.

1. Go to **Accounts → Booster**
2. Each account needs a username set
3. Upload a message text file (each line = one message)
4. Select accounts (minimum 2)
5. Set duration and delay intervals
6. Click **Start Warm-Up**

Accounts find each other via usernames, add each other as contacts, and exchange messages from your file. More lines = more realistic conversations.

> Run the booster for at least **24–48 hours** before using accounts for inviting or messaging.

### 3.7 Session Duplicator

Creates a backup copy of an account session.

1. Go to **Accounts → Duplicator**
2. Select accounts to duplicate
3. Click **Create Duplicate Session**
4. Download or store the duplicate

> Always duplicate valuable accounts immediately after acquiring them. Covers you if the original is revoked.

### 3.8 Restriction Remover

Attempts to lift temp spam blocks and unfreeze accounts.

1. Go to **Accounts → Restriction Remover**
2. Select restricted accounts from Spam Block or Frozen folder
3. Configure: registration date, inviters file, usage description, mode
4. Select a **sticky proxy**
5. Click **Start**

> Telegram may require manual captcha solving. The platform will pause and prompt you.

### 3.9 Creating Chats, Channels & Bots

1. Go to **Accounts → Create**
2. Select type: Chat, Channel, or Bot
3. Select accounts to use as owners
4. Fill in names, descriptions, avatars
5. Click **Create**

## 4. Audience Collection (Parsing)

### 4.1 Collect from Group / Channel

Extracts member lists from any group or channel you have access to.

1. Go to **Audience → Collect from Group**
2. Select an account subscribed to the target group
3. Click **Get Data** to pull the account's chats
4. Select the target or paste a link
5. Choose filter: All participants, Active writers, or By last online
6. Click **Start Parsing**

> One account = one group link. To parse 10 groups, you need 10 accounts.

### 4.2 Collect Active Writers

Collects only users who have sent messages in a chat — the most engaged segment.

1. Go to **Audience → Active Writers**
2. Select account + target group
3. Set time frame (last 7 days, 30 days, etc.)
4. Click **Start**

### 4.3 Collect from Comments

Extracts users who commented on channel posts.

1. Go to **Audience → From Comments**
2. Paste the channel link
3. Select account + number of recent posts to scan
4. Click **Start Parsing**

### 4.4 Collect from Account

Parses audience data from a specific account's subscribed chats.

1. Go to **Audience → From Account**
2. Select the account
3. Click **Get Data**
4. Choose source and filter
5. Click **Start**

### 4.5 Global Search

Searches Telegram's public ecosystem for users, groups, and channels.

1. Go to **Audience → Global Search**
2. Enter keywords
3. Select type: Users, Groups, or Channels
4. Choose account(s)
5. Click **Search**

### 4.6 Language & Gender Filtering

Filter collected audiences by language and gender.

**Language filter:** Load a database → select target languages → apply

**Gender filter:** Load a database → select Male/Female/Mixed → neural network classifies by name patterns

> Gender detection is a statistical approximation, not 100% accurate.

### 4.7 Link Checker

Validates group/channel links before campaigns — removes dead or invalid ones.

1. Go to **Audience → Link Checker**
2. Upload link list
3. Select proxy settings
4. Click **Check Links**
5. Download the clean list

### 4.8 Database Tools

**Merge:** Combine two or more databases into one.

**Exclude / Deduplicate:** Remove overlapping or unwanted users.

1. Go to **Audience → Database Tools**
2. Upload databases
3. Click **Merge** or **Exclude**
4. Download result

## 8. AI Persona System

The Persona System is the platform's key differentiator — a **7-layer AI character architecture** that creates realistic, unique Telegram personas. Each persona has its own identity, personality, communication style, knowledge domain, behavior patterns, media preferences, and social relationships. Personas engage in groups and channels autonomously, generating organic-looking posts, replies, and interactions.

### 8.1 Persona Architecture — The 7 Layers

| Layer | Component | What It Controls |
|---|---|---|
| **Layer 1** | Identity | Name, age, gender, nationality, occupation, avatar, bio |
| **Layer 2** | Personality | Big-5 traits: openness, conscientiousness, extraversion, agreeableness, neuroticism (1-10 scale) |
| **Layer 3** | Communication | Tone (casual/formal/friendly/humorous), verbosity, emoji frequency, typical phrases |
| **Layer 4** | Knowledge | Domains of expertise, opinion stances per topic, expertise level |
| **Layer 5** | Behavior | Posts/day range, active hours, response delay range, reaction/reply probability |
| **Layer 6** | Media | Image source (none, AI-gen, Google Drive, URL), AI image model, prompt templates |
| **Layer 7** | Relationships | Allies, rivals, mention frequencies — for Persona-to-Persona (PPI) dynamics |

### 8.2 Creating a Persona

1. Go to **Personas → New Persona**
2. Fill in the **Identity** layer: name, age, gender, nationality, occupation, bio, avatar URL
3. Configure **Personality** sliders for each Big-5 trait on a 1-10 scale
4. Set **Communication** preferences: tone, verbosity, emoji frequency, and any typical phrases
5. Add **Knowledge** domains and opinion stances (e.g., "crypto: bullish", "privacy: strong advocate")
6. Define **Behavior** limits: posts per day range, active hours, response delays, reaction probability
7. Optionally configure **Media** source for image generation with posts
8. Set **Relationship** links to other personas (allies who agree, rivals who debate)
9. Assign Telegram accounts and target groups/channels
10. Choose **LLM config**: provider (OpenAI, etc.), model, temperature, max tokens
11. Click **Save**

### 8.3 How Personas Engage in Groups

Once a persona is created and assigned to accounts + target groups, it operates autonomously:

**Post Generation:**
- The persona's assigned accounts post to target groups at times matching their behavior layer
- Posts are generated by the AI engine using the persona's full system prompt (identity + personality + communication + knowledge)
- Each post stays under 280 characters, uses the persona's tone and emoji style, and reflects their knowledge domain
- A **diversity checker** ensures no two recent posts share >70% word overlap — posts are always unique

**Reply Generation:**
- When another user (or persona) posts something in the group, the persona may reply based on its `reply_probability` setting
- Replies are in-character, referencing the original message naturally
- Response delay is randomized within the persona's `response_delay_min`/`max` range (typically 5-30 minutes)

**Reactions:**
- The persona may add emoji reactions to posts based on its `reaction_probability` (default 40%)

**Active Hours:**
- The persona only acts during its configured active hours (default 9 AM - 10 PM)
- Outside these hours, it appears dormant — no posts, replies, or reactions

### 8.4 Persona-to-Persona Interaction (PPI)

Personas can interact with each other to create realistic group dynamics:

1. Go to **Personas → PPI Campaign**
2. Select participating personas (minimum 2)
3. Choose interaction mode:
   - **Debate** — personas with rival relationships argue opposing viewpoints
   - **Agreement** — personas with ally relationships support each other
   - **Mixed** — random combination of debate and agreement
4. Set topic or let the AI generate discussion topics
5. Click **Start PPI Campaign**

**How it works:**
- Persona A posts about a topic
- Persona B (ally or rival) detects the post through its relationship layer
- If ally: Persona B adds a supportive perspective ("Great point! I'd add that...")
- If rival: Persona B presents a thoughtful counter-argument
- The conversation thread develops naturally between personas

### 8.5 Human-to-Persona Interaction (HPI)

Real users who reply to persona posts receive contextual, in-character responses. The auto-responder recognizes which persona the user is interacting with and replies accordingly.

### 8.6 Persona Campaigns

Personas can be attached to messaging, engagement, and social proof campaigns:

1. Go to **Campaigns → New Campaign**
2. Select campaign type
3. Under **Persona Settings**, choose one or multiple personas
4. The campaign executor distributes actions across persona-assigned accounts
5. Each action uses the persona's voice, timing, and behavior profile

### 8.7 Persona Diversity & Anti-Detection

Every persona-generated message passes through:

- **Content Diversifier:** Synonym substitution, personal touch (humor/energy markers), typo variation, message length variance based on formality level
- **Post Diversity Checker:** Jaccard similarity comparison against last N posts — rejects content >70% similar
- **Behavioral Fingerprint:** Each persona has a unique fingerprint (typing speed, avg message length, capitalization style, punctuation habits, response latency) — no two personas share the same pattern
- **Activity Pattern:** Each persona gets one of four daily activity archetypes (morning person, evening person, night owl, balanced) with peak/moderate/low hour buckets and weekend modifiers
- **Timing Randomization:** Weighted delay distribution, typing speed simulation, sleep cycle simulation (80% chance of inactivity 2-7 AM)

### 8.8 Managing Personas

**List personas:** Go to **Personas → All Personas** — view all your personas with their tone, tags, and assigned accounts.

**Edit persona:** Click any persona to adjust any of the 7 layers.

**Test persona:** Click **Test Generation** to see a sample post in the persona's voice.

**Delete persona:** Remove a persona and all its associations.

**Bulk operations:** Select multiple personas to assign to campaigns, change LLM config, or delete.

## 9. Anti-Detection System

The Anti-Detection System works alongside personas to make every account behave like a unique real human — eliminating the robotic patterns that trigger Telegram's spam detection.

### 9.1 Behavioral Fingerprinting

Each account gets a unique behavioral fingerprint generated at creation time:

| Fingerprint Trait | What It Varies |
|---|---|
| Typing Speed | 25-80 WPM range |
| Average Message Length | 15-200 characters |
| Emoji Frequency | 0-30% of messages |
| Capitalization Style | Normal, lowercase, or mixed |
| Punctuation Habits | Standard, minimal, or expressive |
| Response Latency Base | 30-300 seconds |
| Active Hours Bias | 6 AM to 11 PM |
| Conversation Style | Questioner, Responder, Observer, or Leader |

Every fingerprint is SHA-256 hashed for uniqueness — no two accounts share a pattern.

### 9.2 Activity Patterns

Each account is assigned one of four activity archetypes:

| Archetype | Peak Hours | Moderate Hours | Low Hours |
|---|---|---|---|
| Morning Person | 8-11 AM | 2-4 PM | 10 PM - 5 AM |
| Evening Person | 7-10 PM | 3-5 PM | 5 AM - 12 PM |
| Night Owl | 11 PM - 3 AM | 6-9 PM | 8 AM - 3 PM |
| Balanced | 10-11 AM, 2-3 PM, 7-8 PM | Mornings/evenings | Midnight - 7 AM |

Weekends get a 0.7-1.3x activity multiplier. Accounts also have away periods (simulated offline time).

### 9.3 Timing Randomization

All actions use human-like timing:
- **Weighted delay distribution:** 70% normal delay, 30% shorter delay (simulating engaged user)
- **Burst patterns:** 40% burst (quick actions), 60% normal spacing
- **Reading time simulation:** Message length / 5 WPM = minimum seconds before reply
- **Typing indicator pulses:** Realistic Telegram typing pulses at 500-2000ms intervals
- **Sleep cycle simulation:** 80% chance of inactivity between 2-7 AM

### 9.4 Content Diversification

Every outgoing message is diversified to avoid content fingerprinting:

- **Synonym substitution:** 30% of eligible words replaced with random synonyms from a 30-word map
- **Personal touch injection:** Humor markers at high humor levels, energy punctuation at high/low energy
- **Typo variation:** Up to 5% of messages get a realistic typo (inverse correlation with formality level)
- **Message length variance:** 0.5x-2.0x base length depending on formality
- **Duplicate detection:** SequenceMatcher against recent messages — rejects >80% similar content

### 9.5 Behavior Profiles

Create and apply behavior profiles per account or campaign:

1. Go to **Settings → Anti-Detection → Behavior Profiles**
2. Click **New Profile**
3. Configure:
   - **Min/Max Delay:** 5-60 seconds (configurable)
   - **Activity Pattern:** Natural, Random, or Burst
   - **Max Actions/Hour:** Per-account rate ceiling
   - **Active Hours:** Time window for operations
4. Assign profiles to accounts or campaigns

### 9.6 Flood Guard

- **Predictive protection:** Detects approaching flood limits before they hit
- **Adaptive backoff:** Increases delay exponentially as limits approach
- **Risk scoring:** Each action type has a risk score — high-risk actions get longer delays

### 9.7 Account Aging

Behavior adjusts automatically based on account age:

| Account Age | Behavior Mode |
|---|---|
| < 7 days | Cautious — very slow ramp-up |
| 7-30 days | Moderate — gradual increase |
| 30-90 days | Relaxed — normal operation |
| 90+ days | Mature — full capacity |

### 9.8 Safety Monitor

Real-time safety scoring across all accounts:
- **Risk factor detection:** Unusual action bursts, abnormal timing, duplicate content
- **Emergency stop:** Triggers automatic campaign pause when risk score exceeds threshold
- **Alert creation:** Notifies admin when unusual patterns are detected

### 9.9 Creating a Behavior Profile

1. Go to **Anti-Detection → Behavior Profiles**
2. Click **Create Profile**
3. Name the profile (e.g., "Cautious Newbie", "Natural User", "Burst Reader")
4. Set min/max delay, activity pattern, max actions/hour, active hours
5. Click **Save**
6. Assign to accounts from the Account Panel or during campaign setup

**View user:** `GET /admin/users/{id}` — full details.

**Update user:** `PUT /admin/users/{id}` — change role, status, name.

**Ban user:** `POST /admin/users/{id}/ban` — deactivates the account.

**Delete user:** `DELETE /admin/users/{id}` — soft-delete with email anonymization.

### 12.2 Order Management

**List orders:** `GET /admin/orders` — filter by status/gateway, paginated.

**Pending orders:** `GET /admin/orders/pending` — quick view of unpaid orders.

### 12.3 Deposit Management

**Pending deposits:** `GET /admin/deposits/pending`

**Confirm deposit:** `POST /admin/deposits/{id}/confirm` — with tx_hash + amount. Creates an Order and upgrades the user.

**Reject deposit:** `POST /admin/deposits/{id}/reject`

### 12.4 Flood Wait Dashboard

`GET /admin/flood-wait` — shows all flood-wait accounts, remaining seconds, and which are ready to resume.

### 12.5 System Alerts

**List alerts:** `GET /admin/alerts` — health drops, flood spikes, bans. Filter by acknowledged status.

**Acknowledge:** `POST /admin/alerts/{id}/acknowledge`

Alerts are created automatically when:
- Account status changes to ban/frozen/flood
- Health check detects a critical drop

### 12.6 Health Checks

`GET /admin/health/run` — triggers a manual health check on all accounts. Results are cached for 120 seconds.

The system also runs automatic health checks every 30 minutes.

### 12.7 Audit Log

`GET /admin/audit-log` — immutable trail of sensitive operations:
- Payment completions
- Credential changes
- User role changes
- Account deletions

### 12.8 Settings

**View settings:** `GET /admin/settings` — all configurable values.

**Update settings:** `PUT /admin/settings` — platform_name, pricing, crypto support, polling interval, API keys.

**Reload infrastructure:** `POST /admin/reload-infrastructure` — reinitializes Telegram connections with updated api_id/api_hash.

### 12.9 Analytics Overview

`GET /admin/analytics/overview` — revenue, user counts, active campaigns, account/groups/persona totals.

### 12.10 Analytics

**Revenue report:** `GET /analytics/revenue?start=...&end=...&group_by=day` — filtered, with breakdown by gateway.

**Account health:** `GET /analytics/account-health/{id}` — trust score, daily messages, status, health score, ping, DC, flood until.

**Campaign progress:** `GET /analytics/campaign-progress/{id}` — total/sent/failed actions.

**Export:** `GET /analytics/export/{campaign_id}?format=csv` — downloads campaign execution logs.

### 12.11 Subscription Expiry

The system runs a background task every hour that:
- Finds expired subscriptions
- Marks them as `expired`
- Downgrades the user's role to `operator`

No manual action needed.

## 13. Campaigns & Automation

### 13.1 Creating a Campaign

1. Go to **Campaigns → New Campaign**
2. Set name, description
3. Choose type: Messaging, Engagement, Invite, or Social Proof
4. Configure target groups and accounts
5. Set message template or reaction
6. Enable AI generation or GPT if needed
7. Click **Save**

### 13.2 Starting / Pausing / Stopping

- **Start:** Campaign moves to RUNNING. The executor picks it up on the next tick.
- **Pause:** Campaign pauses without losing progress. Resume to continue.
- **Stop:** Campaign terminates. Cannot be resumed.

### 13.3 Campaign Types

| Type | What it does |
|---|---|
| Messaging | Sends DMs to target groups |
| Engagement | Adds reactions to posts |
| Invite | Invites users from config to target group |
| Social Proof | Views posts (join + read) |

### 13.4 Execution Logs

Every action is logged in `campaign_logs`:
- Action type (sent, reacted, invited, boosted)
- Status (pending, sent, failed)
- Error message if failed
- Timestamp

View progress via **Analytics → Campaign Progress**.

### 13.5 Rate Limiting

The executor enforces per-account rate limits (default: 5 actions/minute). If an account hits the limit, the executor skips it until the window resets. Accounts in ban status are automatically skipped and marked accordingly.

## 16. Limits & Best Practices

### 16.1 Telegram's Safe Limits

| Action | Safe daily limit |
|---|---|
| Invites per account | 30–50 |
| Messages per account | 30–50 |
| Group joins per account | 5–10 |
| Reactions per account | 100–200 |
| New contacts | 50–100 |

Limits vary by account age, trust level, and proxy quality.

### 16.2 Account Safety

- Warm up accounts 24–48 hours before using them
- Use unique proxies per account
- Use Gmail emails during registration
- Randomize delays — never fixed intervals
- Spread work across multiple accounts
- Run health checks before every major campaign
- Duplicate sessions of valuable accounts immediately
- Never send the same text thousands of times without randomization
- Never ignore flood waits — the auto-resume handles it

### 16.3 Proxy Selection

| Use case | Type |
|---|---|
| General messaging | SOCKS5 or HTTP |
| Registration | Mobile (Sticky) |
| Restriction removal | Sticky (fixed IP) |
| High-volume inviting | Rotating Mobile |
| Health checks | Any |

### 16.4 Recommended Workflow

```
 1. Register / Import Accounts
 2. Generate device parameters
 3. Warm up accounts (24–48h)
 4. Add and check proxies
 5. Run health check
 6. Create Personas with 7-layer profiles
 7. Mass subscribe to target groups
 8. Parse audience
 9. Filter and deduplicate
10. Run inviting or messaging campaign (with personas)
11. Monitor in Analytics
12. Auto-responder handles replies (in-character via personas)
13. Flood auto-resume handles rate limits
```
